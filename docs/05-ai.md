# 05 · 用 AI 写用例和定位失败

这个入口可以把一份需求整理成提示词，也可以调用公司允许使用的 AI 服务，生成用例草稿或失败分析。默认离线运行，不需要 API Key。

**AI 产物只写到 `artifacts/ai/`。框架不会执行它、导入它或自动覆盖现有测试。** Python 草稿通过语法检查只表示“代码可以被解析”，不代表断言正确、定位准确或测试已经通过。需要你审查后再迁入正式测试。

## 1. 先体验，不配置 AI 服务也能运行

在项目根目录、已安装依赖的虚拟环境里执行：

```powershell
uv run python -m autotest ai generate --kind api --input examples/ai/api-requirement.md
```

这会生成 `artifacts/ai/prompt.md`，里面是框架约定和经过基础脱敏的输入文本。打开看一遍，理解 AI 会接收到什么。想再次生成时换一个文件名，或明确加 `--force`。

Web 和 App 的离线示例：

```powershell
uv run python -m autotest ai generate --kind web --input examples/ai/web-requirement.md --output artifacts/ai/web-prompt.md
uv run python -m autotest ai generate --kind app --input examples/ai/app-requirement.md --output artifacts/ai/app-prompt.md
uv run python -m autotest ai analyze --input examples/ai/failure.json --output artifacts/ai/failure-prompt.md
```

`examples/ai/failure.json` 是教学用模拟数据。App 需求模板需要配合自己的安装包、设备和真实定位信息。

`--dry-run` 是明确选择离线模式的别名，不加它也不会联网。`--send` 与 `--dry-run` 不能同时使用。

## 2. 连接兼容的 AI 服务

当前适配器直接调用 `POST {AI_BASE_URL}/chat/completions`，请求使用 `model`、`messages`、`stream: false`；期望文本结果位于 `choices[0].message.content`。公司 AI 网关或本地服务需要支持这个协议；只支持其他 API 协议的服务需要另写适配器。

在根目录 `.env` 中配置公司允许的服务，以下全部是占位值：

```dotenv
AI_BASE_URL=https://your-ai-gateway.example/v1
AI_MODEL=your-approved-model-id
AI_API_KEY=replace-with-your-key
```

`AI_BASE_URL` 填到兼容 API 根路径，例如 `/v1`，不包含 `/chat/completions`；模型 ID 向服务提供方确认。远程服务必须使用 HTTPS，本机服务支持 `http://127.0.0.1:端口/v1`。本地无鉴权服务可省略 `AI_API_KEY`。基础地址不能携带用户名、密码或查询参数。

只有 `--send` 会读取本项目 `.env`。已经存在的系统或 CI 环境变量优先，`.env` 不覆盖它们。把真实 Key 留在 `.env` 或 CI Secret 中，不要加入 Git。

显式发送、生成草稿：

```powershell
uv run python -m autotest ai generate --kind api --input examples/ai/api-requirement.md --send --output artifacts/ai/test_health_draft.py
uv run python -m autotest ai analyze --input examples/ai/failure.json --send --output artifacts/ai/failure-analysis.md
```

生成用例时在线输出必须是 `.py`；失败分析和离线提示词必须是 `.md`。已有文件不会静默覆盖，需要 `--force`。若服务返回无效 Python，命令会报错，不保存可执行草稿。

网络请求设置连接超时 10 秒、读写等操作超时 60 秒；这不是整个请求的总时长限制。请求不自动重试，不跟随服务端重定向。超时后先检查服务端状态和计费情况，再决定是否重新发送。[HTTPX 超时说明](https://www.python-httpx.org/advanced/timeouts/)

## 3. 一份有用的需求应该写什么

AI 看不到整个代码仓库。为了生成能用的代码，请在指定输入文件里提供必要契约：

| 信息 | 示例 |
|---|---|
| 被测行为 | 创建项目、登录、提交 iframe 表单 |
| 接口或定位 | 方法、路径、JSON 字段；role/name/test id；accessibility id |
| 前置条件 | 已登录、指定角色、有效测试数据、设备起始页面 |
| 预期结果 | HTTP 201、返回 id、页面显示项目名；不要只写“请求成功” |
| 清理要求 | 删除本用例创建的数据，失败时也执行清理 |
| 可复用对象 | 已有 fixture 名、Service/POM 类的 import 路径和方法签名 |
| 未知项 | 明确标注待确认，避免 AI 猜测 |

默认提示词已说明 `api_client`、`base_url`、`page`、`settings`、`app_driver` 和页面对象目录。新增自己的 fixture 后，连同用途与返回类型写进需求，或维护 `src/autotest/ai.py` 的 `FRAMEWORK_CONTEXT`。

## 4. 从草稿到正式用例

1. 阅读生成文件，核对接口、字段、业务断言、定位、账号来源和清理步骤。
2. 把共用业务调用或页面动作放进 Service / Page / Screen；不要复制几十份定位。
3. 把审查过的用例复制到 `tests/api/`、`tests/web/` 或 `tests/app/`。
4. 先运行这一条用例，确定真实环境里的结果，再加入 smoke 或 regression 集合。

例如，审查 `test_health_draft.py` 后将其放到 `tests/api/test_health_ai.py`，可以运行：

```powershell
uv run python -m pytest tests/api/test_health_ai.py -v
```

不要把 `artifacts/ai/` 设成 pytest 的测试目录；那里允许存在未完成、需要修改甚至有危险操作的模型草稿。

## 5. 失败时怎么定位

框架在 `artifacts/<本次运行>/failures/<用例>/` 保存 `call.json` 等阶段摘要。选择具体 JSON 后先离线审查：

```powershell
uv run python -m autotest ai analyze --input artifacts/你的运行目录/failures/你的用例目录/call.json --output artifacts/ai/triage-prompt.md
```

确认文本内容后，使用同一个 `--input` 加 `--send`、换 `.md` 输出文件名即可联网分析。分析要求区分“产品缺陷、用例问题、环境或数据问题、证据不足”，标注事实、推测和下一步验证。最终分类仍然需要结合你观察到的接口响应、页面、服务日志判断。

修复定位器应基于最新页面证据；修复断言应基于确认过的业务契约。删断言、吞异常、固定 sleep 或无限重试只是掩盖问题。这个入口会给建议，实际修改由人审查后完成。

## 6. 数据与能力边界

- 只读取 `--input` 指定的一个 UTF-8 文件，最多 128 KiB；不扫描仓库、不附加环境变量、也不读取其引用的附件。请求还包含内置框架说明。
- JSON/YAML 会递归隐藏 password、token、authorization、cookie、api_key 等常见字段；普通文本会匹配常见认证头、Bearer/Basic、密码赋值及 URL 用户信息。
- YAML 输入不接受别名引用（`*name`），请摘出必要字段作为独立摘要，避免小文件展开成大量数据。
- **脱敏不是完整的保密识别系统。** 没有标签的密钥、客户姓名、身份证、业务机密、自定义字段可能仍会保留。发送前需要按公司要求检查和删减；可在 `redaction.py` 扩充规则。
- 截图、视频、trace、APK、IPA 和 App XML 不作为此入口的附件上传；选择 JSON 时也不会跟随其中的附件路径。不要把敏感二进制内容转成文本规避这个边界。
- AI 返回内容可能不可靠，包括恶意或错误代码。入口只做响应结构和 Python 语法检查，不做完整安全审计，也不验证业务正确性。
- 脱敏发生在输入发送前。模型回复保留原文，避免误改 `token = response.json()["token"]` 等代码；输出仍须检查敏感内容，不能直接公开分享。
- 当前单元测试使用模拟 HTTP 响应验证协议和失败分支，未使用你的真实服务、额度或模型验证效果。[HTTPX MockTransport](https://www.python-httpx.org/advanced/transports/#mock-transports)

## 常见问题

| 提示 | 处理 |
|---|---|
| 输出文件已存在 | 换文件名保留历史，或确认后加 `--force` |
| 输出必须位于 artifacts/ai | 从项目根目录运行，并使用 `artifacts/ai/xxx.md` 或 `.py` |
| 需要配置 BASE_URL / MODEL | 配置根目录 `.env` 或环境变量；地址与模型不能自动猜测 |
| HTTP 401 / 403 | 检查 Key、模型权限、公司网关授权 |
| HTTP 404 | 检查根路径是否重复了 `/chat/completions`，并确认服务支持该协议 |
| HTTP 429 | 检查额度和频率限制；当前不会自动重试 |
| 返回格式不兼容 / 空回复 | 确认服务输出 `choices[0].message.content` 的字符串文本 |
| Python 语法无效 | 精简输入，要求输出一个完整 Python 文件；不要直接运行错误回复 |
